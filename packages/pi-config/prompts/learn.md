## /learn — Explore-and-document workflow

Area: $@

**Step 1 — Orient**
1. Check if this area has docs, README, or a well-known resource.
2. Skim the surface: what is it, who uses it, what problem does it solve?

**Step 2 — Dive**
1. Read key entry points, configuration files, or API surfaces.
2. Note patterns, conventions, and surprising design choices.
3. Ask me 2-3 specific questions where the answer would deepen understanding.

**Step 3 — Write**
1. Produce a structured finding: overview, key concepts, how-to, open questions.
2. Keep it short enough to re-read later. Link to source files or URLs where relevant.
3. Save as `.md` in a sensible location (or show me if you're not sure where).
